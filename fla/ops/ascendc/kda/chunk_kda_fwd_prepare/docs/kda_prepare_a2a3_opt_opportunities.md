## 1. 培训文档直接给出的机会（可直接迁移）

### 1.1 尾部 4-head 展开——A5 有，A2/A3 没有

培训 §7.2（**[实测]**）：KernelA 把"一个 chunk × 全 head"改成"chunk × 4-head window"后，
任务数 128 → 3072，最大工作量 480 → 440 工作单位，实测 **+1.10%**（B1H96T8192）与 **+4.55%**（B1H96T16384）；
作者归因是**多核尾波负载均衡改善**，而不是"四份输入同时驻留"。

本仓 `design.md §5`：A5 dense 在"chunk 数不能整除已用核"时，会把剩余 chunk 按 4 个 value head 展开均摊；
**但同一段最后一句写着"变长、A2/A3、已经启用全局 head partition 或 GVA 边界不满足条件的场景仍使用原调度"**
⇒ **A2/A3 拿不到这个尾波收益**。

动作：评估后把 A5 的尾部 4-head 展开移植到 A2/A3（前提：`group_size=HV/HK` 整除 4、尾块不拆 GVA 组、
AIC 与两个 AIV 尾部映射顺序一致、不同核写入互不重叠）。

### 1.2 head 级流水，而不是 pair 回合锁步

培训 §6 的理解性调度："先推进四个 head 的 Stage0，同时允许 AIV 消费已就绪的 dAqk_raw，再执行已就绪的
Stage2……AIC 在等待期间推进其他 head 的 Stage0，或执行已就绪 head 的 Stage2"。

现状：A2/A3 是 **pair 回合锁步**——`wait free[pair] → 两个 AIV 各做一个 head → set ready[pair]`，
AIC 必须等这一对的两个 AIV 都完成才进 C2 ⇒ 单 head 抖动拖慢整对。

动作（P2）：把跨核粒度从"pair 回合"细化到"head 就绪"。**A2/A3 的障碍是 mode 0x2 集合同步**
（AIC 一次 set 唤醒两个 AIV、两个 AIV 都 set 才唤醒 AIC）⇒ 需要改成每组独立 flag
（参考 A5 的 per-subblock slot 语义 0x4 + ready 0/1/16/17、free 4/5/20/21），属改协议，风险最高。

### 1.3 window 大小消融（1/2/4/8）

培训 §7.4 明确："现有记录证明的是相对原调度方式的收益，**未证明 4 优于所有 1/2/8**"；
§7.5 给出驻留代价随窗口线性增长（vNew 4 head 64 KiB、8 head 128 KiB）。
⇒ 在 A2/A3 上做 1/2/4/8 消融（总时长 + 尾波比 + L1/UB 峰值）；差异在噪声内就维持 4 并写明"未证明最优"。

### 1.4 不要重复 KernelA 已回退的尝试（省试错）

培训 §7.4：**P0**（为 dAqk_raw/dq_raw/dv 做专属 L0C ring）差异 ≤0.1%，回退；
**P2**（四份 L1 owner 同时预取完整窗口、多种排队顺序）均未超过 P1，回退。
⇒ 不要先做"专属 L0C ring"或"四份 L1 owner 全窗口预取"这两类改动。

## 2. 19 条约束在本算子上的"体检"结论（可改的点）

| 约束 | 现状 | 可优化方向 |
|---|---|---|
| **16 / 10**（少重复运算 / 不重复搬 GM） | `design §5` 自述：仍按 value-head slot 搬运和归一化 Q/K，多个 value head 映射到同一 Q/K head 时会从 GM 重读 | **按 HK 去重**：norm 只由 GVA 组首 owner 做一次、按 HK 写 workspace，其余 head 读归一化结果（同语义同操作，不违反约束 18）；收益 ∝ `(1−HK/HV)` |
| **15**（少连续同型） | 连续 vector：V0→V1；连续 cube：C4→C5 | V0/V1 已在**同一握手回合**内（跨核成本 0）；C4→C5 仅 `M>32` 执行且 C5 无跨核等待 ⇒ 现状可接受，但需量化确认"任务尽可能少" |
| **4**（矩阵结果给 vector ⇒ 放 UB） | **A2/A3 无 L0C→UB**，C2 的 raw score 只能走 GM relay（20 KiB），C4 复用前 4 KiB 放 T | 不能消除（平台约束）；可查 relay 的**大小与搬运次数**是否最小（V3 是唯一消费者），以及 relay 与 T 的 WAR 是否已最优 |
| **12**（不分 pass/分 tile；一次搬运 + 一轮算完；**A5 上是"一次 VF"，A2/A3 无 VF**） | C2 = 4 个 band 提交（N=16/32/48/64）；V3 的叶子逆用 `SolveLeafRightLooking` 分块前代 | 逐 stage 核对"一次搬完"；叶子逆是**固定块循环**而非数据分趟搬运 ⇒ 应判定合规，但需在 design 写明依据；A2/A3 的容量约束来自 UB（184 KiB）而非 VF 寄存器 |
| **9**（L1 常驻预留 4 份） | L1 已用 368/512 KiB，4 head lane | **144 KiB 余量**可用于预取（P0-3）或常驻；任何新常驻必须按 4 份规划 |
| **13**（无依赖的 cube/vector 驻留空间不重叠） | 当前 V3 用私有区、C4/C5 用 L1 | 若做 V6 提前（P0-2），要重新证明 V6/V3 的 UB 私有区与共享区不重叠 |
| **18**（同语义不同 head 同种操作） | GVA 组首 owner 才写 q_hat/k_hat/rstd | 若做 HK 去重，必须保持"所有 head 走同一条 GM 取数路径"，不能一半 UB 一半 GM |
| **19**（stage 尽量少，但不牺牲其他条） | 8 个 stage | **不建议**合并 V0+V1，但理由不是 A2/A3 容量：A2/A3 上两者复用同一 72 KiB 私有区，合并的内存代价相同；不合并的原因是 **A5 的一次 VF 约束 + §4.4 两平台 Stage 同名同序**（否则破坏逐 Stage 验证）。约束 15 的担忧已被"同一握手回合"消掉。**推论：A2/A3 的边界由 A5 决定，若只为 A2/A3 改界限需在 design 写明平台差异表** |

**P2-3 展开（由"无 VF"这一平台差异推出）**：A5 上"一个 Stage 的数学必须在一次 RegBase VF 内完成"，
所以 Stage 的**容量上限由 VF 寄存器/工作集决定**；**A2/A3 无 VF，容量上限只由 UB（每 AIV 私有 72 KiB +
共享 40 KiB）决定**，且约束 5 允许 vector→vector 的中间量留在 UB（双块）而不落 GM。这意味着
**A2/A3 原则上可以按 UB 预算重新切 Stage**，例如：

- **拆 V3**：`V3a = mask + beta（产出 Aqk 与 L）` → `V3b = 两个 32×32 叶子逆 + 跨叶修正（产出 Akk/B/X0/X1/negX1）`。
  收益：每段 UB 工作集更小（V3a ≈ raw score 20 KiB + Aqk/L 16 KiB；V3b ≈ L 16 KiB + 逆/修正块 ~24 KiB），
  可缩短 `C2 ↔ V3` 的耦合半径；代价：多一次核内同步与一次 UB 换义，且**破坏两平台同名同序**
  （§4.4 要求差异能一句话说清并写进平台差异表）。
- **合并 V0/V1**：内存代价与现在相同（见上表），收益仅是少一个函数边界；**不建议**。

准入条件（沿用 §4 判据）：先做分 Stage 计时证明 V3 是瓶颈段，再用 UB 账证明拆分不挤占其它 Stage 常驻；
否则维持现划分。

## 3. 结构级调度机会（需实测排序）

| 机会 | 变化 | 关键点（任一不成立就放弃） |
|---|---|---|
| **V6 提前**（P0-2） | AIV 侧 `V0→V1→V6` 再等 C2；AIC 侧不变 | ① V6 的 GM 输出对 C7 的可见性（`DataSyncBarrier`/FIX 是否覆盖）② V6 与 V3 同 AIV 顺序执行 ③ 共享区 `kSharedG/kSharedScratch` 换义（`kV3BetaEff=kSharedBase` 必须在 V6 之后）④ 回合数变化后 flag 严格配对 |
| **回合 3→2**（P1-1） | 第二回合合并 C4→C5→C7 | L1 峰值 ≤512 KiB；T/q10/Akk 的 L1 槽位不冲突 |
| **C7 RHS 预取**（P0-3） | C4/C5 期间把 K_beta_g/V_beta 从 GM 预取到 L1 | L1 余量 144 KiB 是否够（每 head 两份 RHS 各 16 KiB）；预取与 C4/C5 的 MTE1/M 事件是否冲突 |
| **C4/C5 ∥ V6** | AIC 做 C4/C5 时 AIV 做 V6 | UB 预算：V3 已用满 72 KiB 私有区、V6 再要 64 KiB ⇒ **184 KiB 下需要重排**（例如把 V3 的 compact raw 挪到共享区） |

关键路径公式（符号由分析计划 D2/D3 填）：

```text
T_now = V0V1 + C2 + V3 + C4C5 + V6 + C7 + 3*delta_flag
T_P0  = V0V1 + max(V6, C2) + V3 + C4C5 + C7 + 2*delta_flag     （V6 提前 + 回合合并）
尾波项 = ceil(工作单位 / 核数) * 单任务时长                        （P0-1 直接改善这一项）
```

## 4. 建议的推进顺序（先测后改）

1. **先补三项基础数据**（分析计划 P2/P3/P4）：`V6` 与 `C2` 的实测时长、`δ_flag` 量级、尾波比（每核 max/avg 工作量）。
   没有这三项，P0-2/P1-1 的收益无法排序。
2. **低风险先做**：P0-1（尾部展开，A5 已有实现）、P0-3（预取）、P1-3（window 消融）。
3. **再做中风险**：P0-2（V6 提前）、P1-1（回合合并）、P1-2（GVA norm 去重）。
4. **最后评估结构级**：P2-1（head 级流水）——改 flag 协议，且 A2/A3 的 0x2 集合同步限制最大；
   建议只在前几项做完、且尾波/锁步仍是主要瓶颈时才动。
5. 全程判据：**L1 位级逐位一致 + 全门禁 + 同机同频 3 warmup×10 次取中位**；调度类改动额外跑 ≥3 轮 hang 看护。
